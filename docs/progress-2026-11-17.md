## 2. 为什么换硬件（11-10 实测的结论）

| 发现 | 结论 |
|---|---|
| 电机负载判断"推到物体" | ❌ 不可用：空载约 70 mNm，噪声 sd 4–20，有物体只多 +5~+14 |
| GRU 接触模型 | ❌ 实机上 12/12 输出约 0.97，没有区分力（训练数据和实机分布不一致） |
| hsv / color 模式 | ❌ 在多模式循环里会卡死（11-03 色标失败的原因）；rgb / reflection 正常 |
| 色标 | ⚠️ 位置随机，沿边巡线基本扫不到 |
| 旧车头 | ⚠️ 颜色传感器太高（白线反射率只有 11–15）、挡在物体路径上、结构晃 |

所以决定：**捕获判断改用触碰传感器，航向改用陀螺仪，搜索改成全场扫描线，底盘换成官方结构。** 不用超声波，因为轮胎只有 33 mm 高，超声波一般装得比这高，看不到它。

### `mission-v3` 分支（任务主流程，还没合并进 main）

流程：

```
start_check → seek_edge → edge_walk（找色标）→ edge_probe（定场地轴向）
            → 扫描线（来回扫，线距 90 mm）→ 触碰捕获 → deliver（物体中心推到色标上）→ release
```

- 航向：陀螺仪 + P 控制，`hold_heading()`（EV3 的 DriveBase 不支持 use_gyro）

- 旧路径（负载判断、GRU、对角线反弹、720° 自标定）的代码都保留，开关默认关闭；`edge_to_finish` 没动

## 5. 已知问题（下一轮要修）

1. **上机必崩**：`mission.py` 从 umath / math 导入 `hypot`，MicroPython 没有这个函数，程序一启动就 ImportError。要改成自己写的 `sqrt(x*x + y*y)`。
2. **物体被推出界**：推板最前端在光斑前 123 mm，等光斑看到白线时物体已经出界了。改法：先用撞边估出边界，之后靠里程计和陀螺仪，在推板前端到线时就停；光斑看到白线只当紧急刹车。
3. **验收标准要改**：规则是轮子压线不算犯规，只要不掉出去就行。仿真把"轮子越过白带"算失败，标准定严了。转弯前要多倒一点，轮子平时就不会出线。
4. **仿真里的物体尺寸不对**：用的是 r = 25 mm，应该是 33.5 mm。另外 5/8 次扫完都没碰到轮胎，要加覆盖图看哪里漏扫了。
5. `OBJ_LEAD_MM` 需要确认，交付精度对它很敏感。
6. 触碰和陀螺仪的读数到底要不要 await，还没在实机上确认（`probe_new_hw` b 段会打印出来）。

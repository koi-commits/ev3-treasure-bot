# Mission v3 — 陀螺航向 + 车道扫描 + 触碰捕获（仅离线验证）

> 状态：**全部只在仿真里跑过，没有任何一条在实机上验证**。本文所有"实测"都指
> `tests/sim.py` 里的仿真结果，不是机器人上的测量。实机数字一律标 [TBD]。
>
> 几何基线 2026-11-17（新底盘）：光斑只在两轮轴线中点前方 **20 mm**（原来是 60），
> 推板前沿 143 mm ⇒ 前横梁 CB≈27，轮胎 Ø67×33（r=33.5），目标物中心坐进漏斗时
> 约在轴心前方 **100 mm**（`OBJ_LEAD_MM`，[TBD] 待复核）。

## 1. 流程

```
start_check ─► seek_edge ─► edge_walk（找色标）─► edge_probe（定轴向）
      ─► lane_sweep 正向 ─► lane_sweep 反向 ─► 触碰捕获 ─► deliver ─► release
```

| 阶段 | 做什么 | 为什么这样做 |
| --- | --- | --- |
| 起步自检 | 光斑若压在白线上，先倒车再走 | 起点随机，可能贴着边 |
| 寻边 | 直行到见白，倒车，然后开始 | 复用已实机验证的 `seek_edge` |
| 找色标 | `edge_walk`：垂直撞边 → 退到 80 mm 内侧 → 沿边走 200 mm → 再撞 | 色标贴在场地内侧边缘；垂直进出才不会让轮子压进白带 |
| 定轴向 | `edge_probe`：撞白采点 ×3，最小二乘拟合边方向 | 车道要垂直于这条边 |
| 扫掠 | 车道垂直于边，间距 90 mm，逐条推进；见白/到墙角/连续两条车道不见白就停 | 覆盖式搜索轮胎 |
| 捕获 | 触碰开关连续 3 个样本 pressed | 轮胎被 V 形推板收进漏斗、顶到挡板 |
| 交付 | 先到场内待命点，再沿"色标所在那条边的法向"直线推进，让**轮胎中心**落在色标上 | 只走前进弧线，绝不倒车推 |
| 释放 | 倒 150 mm 停车，打印 `DELIVERED (unverified, check by eye)` | 机器人看不见物体，必须目视判定 |

`MISSION_MODE`：`sweep`（只扫、打印色标估计与车道图）、`capture`（扫到触碰即停）、
`full`（完整任务）。`edge_to_finish` 仍然可用，是已实机验证的老路径，行为未改。

## 2. 参数（`src/config.py` 第 11 节）

| 参数 | 值 | 说明 |
| --- | --- | --- |
| `USE_GYRO` / `USE_TOUCH` | True | 航向用陀螺、捕获用触碰 |
| `GYRO_SETTLE_MS` | 2000 | 起步静置 2 s 后 `reset_angle(0)` |
| `KP_HEADING` / `MAX_TURN_RATE` | 2.0 / 120 | `hold_heading` 的 P 增益与转向限幅 |

| `EDGE_WALK_MM` / `EDGE_WALK_MS` | 200 / 300000 | 找色标时每步沿边走多远 |
| `EDGE_PROBE_N` | 4 | 撞白采点次数（三点定线，多采一个冗余） |
| `LANE_SPACING_MM` | 90 | 车道间距 [TBD]（推板通口约 105 mm） |
| `LANE_MAX_MM` | 1236 | 单条车道长度上限 |
| `BACKOFF_MM` | 80 | 撞到白带后倒车量 |
| `LANE_END_MM` | 150 | 车道刚出发就见白 ⇒ 判定这条墙到头 |
| `DELIVER_TOL_MM` | 8.0 | 交付落点容差（原来是 20，把 ±10 mm 判定窗吃掉了） |
| `MARKER_MIN_HITS` / `MARKER_REJECT_MM` | 3 / 150 | 色标点数与离群剔除 |

GRU 影子 / 对角线反弹 / 720° 自标定。

## 3. 离线结果（`tests/evaluate.py`，20 seeds × 2 类场景，一次性）

| 场景 | 任务成功 | 可接受成功 | 轮子越白带 | 物体出界 | 虚报成功 | 中位用时 |
| --- | --- | --- | --- | --- | --- | --- |
| 物体在场内（`object_interior`，r=25） | **8/20** | 0/20 | 20/20（51–57 mm） | 4/20 | 0 | 321 s |
| 物体靠边（`object_near_edge`，距边 40–100 mm） | **0/20** | 0/20 | 20/20 | 11/20 | 1 | 293 s |

- 成功的那些次落点误差 6–7 mm（判定窗 ±10 mm）。
- `acceptable` 恒 0 的原因是 `wheel_max_out` 51–57 mm > 40 mm 白带宽度，见"已知限制"。
- `sweep` 模式单独跑：色标在 70 s 内找到（3 次撞边）。
- 靠边物体基本失败：车道在边上结束，推板还没把轮胎收进漏斗就先把它顶出界。

## 4. 已知限制（都要在实机上先确认再谈"能用"）

1. **轮子会压白带**：光斑只前伸 20 mm，而半轮距 57 mm。只要光斑贴到白线，内侧轮
   就已经越过 40 mm 的带子（仿真实测 51–57）。旧底盘 60 mm 光斑恰好等于半轮距，
   所以老代码没这个问题。要真正满足"轮子不越线"，需要在离边留 standoff 的前提下
   重新设计贴边动作，或者把光斑前移（改机械）。
2. **搜物时会把物体顶出场**（2/8）：车道横穿轮胎时把它推到边上，个别种子推过了白带。
   交付阶段不会（交付前会检查 object_out）。
3. **扫掠覆盖不全**：8 seeds 里有 5 次"扫完没碰到轮胎"。车道间距 90 mm 与光斑 20 mm
   的组合下，轮胎可能正好落在两条车道之间。需要更小的间距或之字形路线。
4. `OBJ_LEAD_MM=100` 仍是 [TBD]：交付落点对它很敏感（差 10 mm 就出判定窗）。
5. 陀螺航向依赖 `GYRO_POSITIVE_DIRECTION`，实机必须先用 `probe_new_hw.py` 的 c 段测出来。

## 1. 今天修了什么

| 问题 | 原因 | 改法 |
|---|---|---|
| 起点靠墙角时轴向定错，整场只扫一小块 | `edge_probe` 斜撞会分别撞到两条互相垂直的墙，直线拟合必然失败 | `boundary.fit_axis()`：按"同墙点必有一个坐标相等"配对聚类，枚举 0–180° 找最一致的轴向；再用撞击朝向选沿墙解 |
| 沿墙方向的观测点被当成新墙，空地上就停车 | `Boundary.observe()` 把每个点的两个坐标都记成极值 | 按行驶方向里更对齐的轴判断撞的是哪类墙，只记**这条墙的法向位置** |
| 每条车道走 ~300 mm 就被围栏截停 | 未知墙用短先验兜底，先验比真实场地短 | 空车围栏只信已观测到的墙；未知墙交给颜色传感器。携带时才保留短先验 |
| 红纸盖住白线，机器人可能从纸上开出场 | 红色只算终点标签，不算边界 | `is_boundary()`：红/白都触发急停、倒车、`Boundary.observe`；所有扫描/推送阶段统一使用 |
| 纸在墙上，围栏看出去 143 mm，永远看不到 | 推板围栏挡住光斑 | 找纸时关围栏、贴墙 60 mm 扫；扫完再恢复 |
| 捕获后一转弯就丢 | 擦碰也会压住挡板，去抖 150 ms 不够判"坐实" | `seat_ok()`：捕获后低速前进 400 ms，触碰必须持续按住，否则当没抓到 |
| 停在场边的轮胎会被找纸扫描顶出界 | 捕获后原地停车，正好在贴墙扫描的路径上 | 先把轮胎推到**场内中心**再倒车留下；扫描前转 180° 背对轮胎 |
| 纸被当成一个点，交付目标是猜的 | 纸是方形，需要沿墙范围与内沿 | 找到红纸后用 25 mm 探针、二分测两条沿墙边；红读数起始点给纸内沿；目标 = 纸在场内部分的中点 |
| 待命点导航在纸边起步就误判 lost | 围栏只按当前朝向算 | 按"到目标的方向"查围栏 |

## 2. 红纸模型（用户 2026-11-18 确认）

- 方形红纸压在白色边界线上，盖住部分白线；边长 `MARKER_SIDE_MM = 150` [TBD - 量纸]，
  矩阵同时测 100 / 150 / 200 mm。
- 纸中心相对白线中心线随机向内偏移 `[-side/4, +side/4]`，保证始终盖住整条 40 mm 白带。
- 目标 = 纸**位于场内那部分**的中心：沿墙取纸中心，横向取白线内沿到纸内沿的中点，
  永不越过白线内沿。场内宽度 < 20 mm 仍取中点并打印提示。
- 交付误差 = 轮胎中心到该目标点的距离；成功 = 轮胎中心落在纸的场内部分。

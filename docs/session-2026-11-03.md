### 1.2 为什么需要包装脚本

Pybricks CLI 默认走 Windows 命名管道 IPC，并且在 `%LOCALAPPDATA%\pybricks`、
`%TEMP%\pybricks` 建私有目录。这两条路径都被本机沙箱拒绝：

```
PermissionError: [WinError 5] 拒绝访问: 'C:\Users\<username>\AppData\Local\Temp\pybricks'
  （pb_core\paths.py:171 ensure_private_dir）
PermissionError: [WinError 5]
  （pb_core\ipc\backend\windows.py:173 create_pipe_connection，沙箱禁止打开命名管道）
```

用 `pb_core/paths.py` 的官方覆盖点绕开：

| 环境变量 | 值 | 作用 |
|---|---|---|
| `PB_RUNTIME_DIR` | `<PROJ>\.pb\runtime` | lock / cookie / socket |
| `PB_STATE_DIR` | `<PROJ>\.pb\state` | hub 记忆状态 |
| `USERPROFILE` | `<PROJ>\.pb\home` | platformdirs 的 log/cache 走这里 |
| `PB_ENDPOINT` | `tcp://127.0.0.1:47823` | 绕开命名管道 |
| `PB_SERVICE_CMD` | `D:\python\python.exe -m pb_service --idle-timeout 60` | 后台服务命令 |

还有一条硬约束：**沙箱在每条 shell 命令结束时回收整个进程树**，所以 pb 后台服务
活不过一次命令调用 → 必须把 `service start → connect → run → service stop` 放进一次调用。

因此新增两个 .cmd 包装（PowerShell 执行策略禁止跑 .ps1）：

- `pb.cmd` — 设好上述环境变量后透传参数给 `pb.exe`，供单条命令手工使用
- `pbrun.cmd` — 一次完成 `service start → connect → run → service stop`

用法：

```bat
pbrun.cmd src\demo_edge.py
```

> 注意：`pbrun.cmd` 里所有路径用 `%~dp0` 相对项目根，不要硬编码绝对路径。

### 1.3 踩到的三个 pb CLI 坑（已修）

1. **`The hub would not store the program`**
   上一次被中断的程序还驻留在 hub 上。→ `pbrun.cmd` 在 run 之前先执行 `pb stop`。

2. **`No hub selected`**
   `pb stop` 不带 `--hub` 会把"当前使用的 hub"选择清掉，导致紧接着的 `pb run` 失败。
   → `stop` 和 `run` 都显式带 `--hub Hamster`，且 stop 之后再 connect 一次。

3. **`ERROR: Input redirection is not supported`**
   `timeout /t 1` 需要 stdin 上有控制台。→ 改用 `ping -n 2 127.0.0.1 >nul` 做 1 秒等待。

## 2. Pybricks 4.x 的代码约束（实机踩到，必须遵守）

### 2.1 设备对象必须在模块顶层构造

```python
# 正确
from pybricks.hubs import EV3Brick
ev3 = EV3Brick()
left = Motor(Port.A, Direction.CLOCKWISE)

async def main():
    await run_task(...)
```

在 `async` 函数里 `Motor(port)` / `ColorSensor(port)` 会抛：

```
RuntimeError('This can only be called before multitasking starts.')
```

→ 所以新增了 `hardware.py` 作为**唯一设备构造点**，所有脚本 `from hardware import ...`。

### 2.2 MicroPython 异常没有 `__name__`

```python
type(e).__name__   # AttributeError: type object 'RuntimeError' has no attribute '__name__'
```

→ 用 `repr(e)` / `e.args`。

### 2.3 ColorSensor 在 4.1.2 上没有 `lights_on/lights_off`

可用属性：`ambient / color / detectable_colors / hsv / reflection / rgb`。

### 2.4 格式化坑

`hsv()` 的 `.s` / `.v`、`ambient()` 返回 **float**，
`"{:5d}".format(x)` 会抛 `ValueError: unknown format code 'd' for object of type 'float'`。
→ 用 `{}` 或 `{:.1f}`。

## 5. 沿边巡线算法：从比例控制到三状态机

这是本次会话最核心的工程进展。

### 5.1 第一版：归一化比例控制（`edge.follow_edge`）— **实机失败**

```python
err = (refl - threshold) / span
steer = clamp(-side * gain * err * STEER_LIMIT, ±STEER_LIMIT)
drive.drive(speed, steer)
```

现象：**"扫到白边、有转向、但是冲出白边"**。

根因：`drive.drive(speed, steer)` 会**保持前进速度**。等传感器读到白色时，
车头已经压进白区；比例项虽然打满舵，车仍在向前推进，于是越界。

> 保留该函数在 `edge.py` 里作为参考，但 `demo_edge.py` 已不再使用。

### 5.2 第二版：见白原地转（`follow_edge_bangbang` v1）— **转角抖振**

- 深色区：前进 + 朝白边偏 22 °/s
- 白区：原地转向深色侧，直到不白为止 + 90 ms 余量

现象：**"扫到白边后未冲出，但在转角处来回转向前后移动"**。

根因：只要一读到深色就立刻恢复斜向逼近，刚转出白边就马上又斜着撞回来，
在拐角处形成**抖振**（反馈回路太快）。

### 5.3 第三版：三状态机（当前版本）— **实机通过**

`src/edge.py` 的 `follow_edge_bangbang()`：

| 状态 | 行为 |
|---|---|
| `CRUISE` | 60 mm/s 前进 + 朝白边偏 22 °/s，斜向逼近边界 |
| `ESCAPE` | 见白立刻**原地**转 130 °/s，**固定 350 ms（约 45°）**，不能提前结束；转完仍在白区就再续（最多 2 次，处理内转角） |
| `CLEAR` | 逃逸后**盲走 400 ms**，期间**忽略传感器**，切断抖振的反馈回路 |

关键设计：`CRUISE` 不会因为"看到深色"就重新触发逼近——必须先走完 `CLEAR` 的 400 ms。

```python
CRUISE, ESCAPE, CLEAR = 0, 1, 2
away   = -side * turn_rate        # 离开白边（原地）
toward =  side * approach_steer   # 朝白边（前进中）
```

参数（`config.py`）：

```python
FOLLOW_SPEED      = 60    # mm/s 沿边前进速度
APPROACH_STEER    = 22    # deg/s 朝白边侧的偏转
EDGE_TURN_RATE    = 130   # deg/s 见白后原地转向速度
EDGE_ESCAPE_MS    = 350   # 必定原地转的时长（约 45°）
EDGE_CLEAR_MS     = 400   # 逃逸后盲走、忽略传感器的时长
```

## 6. 标定与实测数据

### 6.1 黑白标定（`src/calibrate.py`）

| 表面 | n | min | max | avg |
|---|---|---|---|---|
| 黑（场地深色面） | 30 | 0.9 | 1.1 | **1.0** |
| 白（白纸） | 30 | 11.2 | 11.3 | **11.2** |

阈值 = (1.0 + 11.2) / 2 ≈ **6.1**。

> 绝对量程偏低（EV3 颜色传感器贴白纸通常能到 ~70），怀疑传感器离地偏高或 LED 偏弱，
> 但 1.0 vs 11.2 有 **10 倍分离**、噪声 < 0.2，判定可用。

### 6.2 真实场地实测（`src/probe_live.py`，手推 30 s 跨白边）

```
low20 = 0.7    high20 = 11.5    span = 10.7    max = 14.5
过渡在 0.5 s 内完成（很陡）
```

据此把 `config.py` 更新为：

```python
BLACK_REFLECTION = 0.7
WHITE_REFLECTION = 12.0      # 场地实测 high20=11.5, max=14.5
EDGE_CONFIRM_SAMPLES = 2     # 50ms x 2 = 100ms；70mm/s 时越界量约 7mm
```

阈值为 **6.35**（`edge_threshold()` 自动计算）。

### 6.3 用户确认的场地条件

- 场地地面：**深色（黑/深灰）**
- 边界：**白色**（比地面亮）
- 与 `config.py` 的阈值方向一致，**不需要反转逻辑**

### 6.4 `demo_edge.py` 实机运行记录

| 轮次 | 每段距离 | white_frac | edge_twists | 现象 / 结论 |
|---|---|---|---|---|
| v1 比例控制 | 555 mm（恒定） | — | — | **冲出白边**，失败 |
| v2 bang-bang | 374 / 365 / 264 mm | 0.15 / 0.16 / 0.31 | 5 / 6 / 11 | 不再冲出，但**转角抖振** |
| v3 三状态机 | 337 / 389 / 377 mm | 0.17 / 0.10 / 0.13 | 5 / 4 / 5 | **通过** |

`white_frac` 定义：巡线期间读到白色的样本比例。理想值 0.1–0.3（只在锯齿顶端压到白边）；
≈1.0 表示整个跑到白区里去了；≈0 表示根本没碰到边。

**用户目视确认（v3）**：
> "扫到白边后会轻角度转向，然后往前走一段后往白边靠，扫到白边后重复刚刚的动作；拐角处的转弯现在相对丝滑。"

# 随机目标物：搜索、推送与交付方案

> 状态：代码已实现并通过仿真（`mission.py` 的 `full` 模式），**全部待实机验证**。

## 1. 约束

- 唯一的外部传感器是**朝下**的颜色传感器，只能看到光斑下方几毫米的地面。
- **它不能发现前方物体**。只有车压到物体上方时才"看得到"，而推板在车前，物体永远到不了光斑下。
- 可用的内部信号只有两个电机的编码器和控制器状态：`Motor.load()`（估计负载，mNm）、`DriveBase.stalled()`、`distance()`、`angle()`。
- 保留底盘，尽量不加硬件。被动推板（纯 LEGO 结构件，无电子）不算新增传感器。

## 2. 结论：被动 V 形推板 + 随机反弹覆盖 + 负载判定 + 里程计交付

| 环节 | 方案 | 实现 | 备选 |
|---|---|---|---|
| 找终点 | 寻边 → 已验证三状态巡线 → 色标确认后记录里程计位姿 | `edge_then_follow` | — |
| 搜索 | **随机反弹覆盖**（`SWEEP_PATTERN="bounce"`） | `bounce()` | 往返扫描线 `"lanes"`（需几何标定，仿真成功率较低） |
| 捕获 | **V 形推板**被动收拢物体 | 机械 | — |
| 判定推到物体 | **负载抬升**（`LoadMonitor`）；推不动时 `stalled()` | `drive_until(monitor=…)` | `CAPTURE_MODE="off"` |
| 交付 | 按里程计走回记录的终点位姿（`DELIVERY_MODE="odometry"`），失败自动改沿边找色标 | `deliver()` | `"edge"` |
| 放下 | 色标确认后前推 `FINISH_PUSH_MM`，倒车 `FINISH_BACK_MM` 留下物体 | `finish_stop()` | — |

### 为什么选随机反弹而不是往返扫描线

仿真对比，每组 20 个随机种子：

| 覆盖方式 | 无误差 | 里程计 ±8% 误差 | 车体出界 |
|---|---|---|---|
| bounce | **20/20** | **20/20** | 从未 |
| lanes | 17/20 | 18/20 | 有（拐角原地转） |

扫描线依赖两个前提：一是对"终点所在边"方向的估计（由沿边锯齿点拟合，误差约 ±10°），二是绝对航向。只要扫描线稍斜，就会留下漏扫的缝，在角落原地转时光斑还会扫出白边。

随机反弹每一段都以"直行到白边"结束。转向前先倒车 `SWEEP_END_BACK_MM`，这个距离要不小于光斑前伸量加 20 mm。它完全不依赖几何标定，代价是平均用时更长，大约 2 分钟（扫描线约 1.7 分钟）。

几何标定完成后，可以在实机上再比较一次 lanes。

## 3. V 形推板设计要求（请 DSH 按此搭）

```
          光斑 ●            ← 推板顶点在光斑前方 ≤ 30 mm
        \       /
         \     /            ← 两臂夹角 60–90°，开口宽 ≥ 2 × 物体直径
          \   /             ← LANE_WIDTH_MM ≈ 0.8 × 开口宽
     ┌─────────────┐
     │   车  体     │
     └─────────────┘
```

1. **顶点前伸 ≤ 30 mm（相对光斑）**。到达白边时，光斑先看到白，车就停下。如果顶点远远领先光斑，物体会先被推出白边。到终点时也一样：物体应当和光斑差不多同时进入色标区。
2. **臂不能挡住光斑、不能碰到光斑周围的地面**，否则会改变反射率读数。改完推板后**必须重跑第 1 步 demo_edge 回归**。
3. **离地 2–5 mm**，避免摩擦地面抬高空载负载、降低信噪比。
4. **够深**：物体要能在车原地转 45°（ESCAPE）时不滑出。
5. 结构要刚，推物体时不能变形，否则负载信号会变弱、变得不稳定。

## 4. 负载判定的原理与风险

- `LoadMonitor` 先跳过每段直行起步的 6 个加速样本，再用 12 个样本测出本段的空载均值。**基线只会往下更新**，因为空推板的负载一定最小。这样即使第一段一开始就推着物体，基线学得偏高，下一段空载时也会被纠正（`test_baseline_learned_with_object_recovers`）。
- 触发条件：滑动均值高于基线 + max(4σ, `LOAD_ABS_MARGIN`)，并连续 4 个样本保持。
- **最大风险：物体太轻，负载抬升被噪声淹没。** `probe_load.py` 专门测这一点。如果实测分不开，有三条退路：
  1. 确认规则是否允许给物体加配重，或换用更重的目标物。
  2. `CAPTURE_MODE="off"`。这时只会扫场，不会主动交付，任务不能完成，只能作为过渡。
  3. 若后续允许加硬件：在推板顶点放一个**触碰传感器**，可以一步解决检测问题。也可以加超声波传感器做前方探测。

## 5. 已知风险（全部待实机）

| 风险 | 影响 | 缓解 |
|---|---|---|
| 交付途中沿边巡线的原地转把物体甩出推板 | 到达终点但物体不在 | 默认用里程计直线交付；推板做深 |
| 里程计误差（未标定时 5–10%） | 交付直线偏离终点 | 中途分段重新瞄准（`goto_pose` 3 段）；到边后自动改沿边找色标 |
| 白边外是深色、白边又窄 | 拐角原地转时光斑可能扫到外面 | 已加出界判定：直线走过对角线仍不见白，就走回最近的见白点并穿过白边回到场内（仿真全部恢复） |
| 物体被推到白边上 | 下次碰到时一起被推出界 | 推板顶点前伸量要小（第 3 节第 1 条） |

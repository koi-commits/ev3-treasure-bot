# 随机目标物：搜索、确认、推送与交付

> 状态：代码已实现，经接触式物体仿真 + MicroPython 执行验证。**全部待实机验证。**
> 第一版文档的结论（"20/20 成功"）建立在理想化物体模型上，已被推翻，见 §6。
> 流程里还有一步"场上转角自标定"（`calibrate_and_map()`），见 §2。

## 1. 约束（决定了一切）

- 唯一外部传感器是**朝下**的颜色传感器，它**看不到前方物体**。机器人永远不能"看见"物体是否在推板里，只能间接推断。
- 可用的间接信号只有电机：`Motor.load()`（负载估计，mNm）和 `DriveBase.stalled()`。
- 被动推板（纯 LEGO 结构件）不算新增传感器。
- **推板必然在光斑前方**，所以物体总是比光斑先越过白线。这是"把物体推出场地"风险的根源，软件无法消除，只能靠几何尺寸压低（§3）和流程避开（§2）。

## 2. 流程

```
找终点（已验证巡线）──► 场上转角自标定 + 色标定位（约 30 s：离边、原地转 720°、回到同一条边沿边走过色标）
       ──► 搜索：对角线反弹 ──► 负载嫌疑 ──► tap + seat 确认 ──► 推送：纯追踪（只走弧线，不倒车、不原地转）
       ──► 先到场内待命点，再正对色标直线推进，让【物体中心】停在目标点 ──► 倒车放下
```

| 环节 | 做法 | 为什么（仿真依据） |
|---|---|---|
| 色标定位 | 首次确认后继续沿边，记录所有光斑落在色标上的位置，取中心，再往场内移 `MARKER_INSET_MM` | 首次确认点在色标**角上**，按它交付会落在色标外（旧版主要失败模式） |
| 场地轴向 | 色标所在边的锯齿点做最小二乘直线拟合（只用拐角之后的共线点） | 矩形场地所有边 ≡ 轴向 (mod 90°)，后面的反弹方向和自标定都靠它 |
| **转角自标定** | 退到场内、原地转 720°、回到同一条边再测一次边方向；残差 ÷ 转过的角度 = 转角比例误差 | **最关键**：1% 转角误差就让交付成功率从 ~50% 掉到 ~25%，3% 时几乎全失败且大量虚报（§5） |
| 搜索 | 沿场地**对角线方向**（轴向 + 45° ± 15°）直行到边，倒车、转 ±90° | 碰边入射角 ≥ 30°，光斑先于边侧轮子碰到白线；随机角度反弹时，浅角度碰边会让轮子整个越过白带（8/12 → 1/12） |
| 捕获判定 | 负载持续高于空载基线（基线只往下更新）→ **嫌疑**；再做 tap + seat：倒车 50 mm 松开物体，低速前进，"自由段 / 重新接触早段 / 继续推进晚段"三段负载对比 | 只看阈值时，负载漂移会让机器人"交付"一个根本没推着的物体。晚段用来排除物体只被推板**外侧**蹭着走 |
| 推送 | 纯追踪：一直前进，转向率 ∝ 方位角（≤ 35°/s，半径约 115 mm） | 原地转 ≥ 90° 会把物体甩出推板，前进中的弧线基本不会（§4） |
| 推送中掉了 | 负载回落到空载水平且持续 12 个样本 → 判定丢失，退回搜索 | 宁可重新找，也不虚报交付 |
| 交付 | 先到目标点场内侧 250 mm 的待命点，再正对色标推进，按里程计让物体中心到目标点；途中光斑先压到色标也立即停 | 物体在光斑前约 50 mm；从场内垂直接近，物体停在色标里而不是被推过白线 |
| 结果报告 | `DELIVERED via ... (unverified)` | 机器人无法确认物体在色标上；结果必须由人目视判定 |

## 3. 推板设计要求（请 DSH 按此搭）

```
              ╲            ╱        ← 臂尖：开口 ≥ 2.5 × 物体直径
               ╲          ╱
                ╲   ●    ╱          ● = 物体落座位置（顶点前 r/sin(半角)）
                 ╲      ╱
                  ╲    ╱            ← V 顶点：在光斑前方 ≤ 15 mm
                   ╲  ╱
               ┃    ╲╱    ┃         ← 侧板：车身两侧直线延长到臂碰到车宽处（必须有！）
               ┃    ◎     ┃         ◎ = 颜色传感器光斑
            ┌──┸──────────┸──┐
            │     车  体      │
```

1. **侧板（建议）**：车身侧面要直线延伸，直到与推板臂相接。否则"臂外侧 + 车头"会形成凹角，物体会卡在那里被推着走：负载判定显示"推着物体"，但物体偏离中线约 40 mm。加了 seat 检查后，仿真里有无侧板差别不大（8/12 vs 8/12），但侧板能从物理上消除这种情况。
2. **顶点尽量靠近光斑**（≤ 15 mm）。物体中心领先光斑的距离 ≈ 顶点前伸 + r/sin(半角)，这个领先量就是物体越过白线的深度。
3. 臂夹角 70–90°，深度能装下整个物体。
4. **物体与推板之间摩擦要小**（光滑件）。高摩擦（μ ≈ 0.6）时即使弧线转向也容易甩出，仿真成功率 4/12。
5. 推板底边离地 2–5 mm，不碰光斑周围的地面。改完推板必须重跑 demo_edge 回归。
6. 量出 **OBJ_LEAD_MM**（物体落座后中心到两轮轴线中点的前向距离），填进 config。交付精度直接依赖它。

## 4. 物体保持（仿真接触模型）

推板里落座的物体，经过各种转向后是否还在口袋里（Y = 在）：

| 推板-物体摩擦 | 原地转 45/90/135° | 前进弧线 ω=60°/s | ω=25–35°/s |
|---|---|---|---|
| μ = 0.1 | Y Y Y | Y Y Y | Y Y Y |
| μ = 0.3 | Y n n | Y Y Y | Y Y Y |
| μ = 0.6 | Y Y Y / n n n（依几何） | Y Y n | 部分 |

结论：推送中只用前进弧线；推板要光滑。

## 5. 敏感性（仿真，各 12 次，可接受成功 = 物体中心在色标上 ∧ 无轮子越过白带 ∧ 物体未出界）

完整矩阵见 `docs/offline-2026-11-03.md` §10.1。要点：

| 条件 | 可接受成功 |
|---|---|
| 基准（物体在场内） | 8/12 |
| 物体靠边（距白线 40–100 mm） | 3/12：找终点时沿边就把物体推出界（结构性问题） |
| 物体轻（负载 10 mNm） | 2/12：检测不到，物体在搜索碰边时被推出界 |
| 物体重（负载 40 mNm） | 9/12 |
| 推板-物体摩擦 μ=0.6 | 1/12 |
| 转角 −3% / 距离 +3%，有场上自标定 | 8/12 |
| 同上，关闭自标定 | 3/12 |

## 6. 第一轮 → 第二轮：被推翻的结论

| 第一轮说法 | 第二轮事实 |
|---|---|
| full 模式 20/20 | 理想模型里，物体一进推板口就被"吸"在顶点、任何转向都不掉，只有倒车才放开。接触模型下同一套代码 0/8 |
| 负载阈值 = 推到物体 | 漂移与加速度会误触发，机器人随后"交付"了一个根本没推着的物体 |
| 交付到首次确认点 | 首次确认点在色标角上，物体落在色标外 |
| 随机角度反弹安全 | 浅角度碰边时，轮子在光斑看到白线前就越过白带 |

## 7. 剩下的结构性风险（只有改硬件或改规则理解才能根治）

| 风险 | 原因 | 能做的 |
|---|---|---|
| 靠边物体在沿边找终点时被推出界 | 推板在光斑前方，沿边巡线就是贴着白线走 | 推板顶点尽量后缩；确认规则："物体压线/出界"怎么判 |
| 轻物体检不出 | 负载信号淹没在噪声里 | `probe_load.py` 实测；不行就（若规则允许）给推板顶点加触碰传感器，可一步解决 |
| 航向漂移 | 无陀螺仪 | 已有场上自标定；若允许加陀螺仪传感器，可直接修正里程计（EV3 DriveBase 不支持 use_gyro，需手动融合） |
